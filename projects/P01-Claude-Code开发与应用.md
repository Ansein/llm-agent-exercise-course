# P01：Claude Code开发与应用

[课程总览](../README.md) · [来源映射](../docs/长图来源与课程映射.md) · [统一验收](../docs/考核与验收.md)

## 业务任务与角色

研发缺陷修复周期长、AI补丁不可验证、跨会话进度丢失。交付一个具有独立验证与恢复能力的教学编码Harness，并开展Codex对照。

角色：开发者、代码审阅者、技术负责人。本项目沿用长图项目编号，任务细节、课时与指标由本课程补充设计。

## 数据与输入契约

一个本地教学订单服务，4个预置缺陷、12条公开业务测试、8条隐藏验收测试；故障覆盖重复请求、权限判断、边界分页和时间处理。教师课前制作基准提交与金标准测试。

关键字段：`task_id、repo_revision、acceptance_ids、worktree_path、status、artifact_paths、tool_trace、budget`。

训练/开发、验证、测试须按客户/文档族/时间等实际泄漏单位划分；具体比例不足时由教师在开课前补齐并冻结。接口返回错误码与来源，不把缺失值改为猜测值。

## 业务流程与技术对照

流程：复现缺陷并锁定起始版本→在工作副本中修复→独立测试→审阅diff→中断恢复→合并回归。

非大模型基线及演进：人工IDE+脚本测试；随后比较无持久化编码Agent与有Harness运行时。

至少保存基线和一个改进方案的逐样本结果；完成率、耗时和成本使用同一批任务。发现复杂方案无收益时，可以保留基线并给出证据。

## 必做实验与异常注入

- 审查补丁是否只满足表面测试，补充边界用例并生成交付说明
- 加入“模型声称完成但测试失败”样本，让Harness维持未完成并给出错误证据
- 测试越界路径和未批准网络访问，确认由沙箱或工具策略阻止

专项故障集：测试伪通过、上下文重置、工具超时、冲突合并、越界读写。至少保留输入、预期、实际结果、执行轨迹和修复后回归。外部动作默认使用模拟接口；租户隔离由服务端与执行环境控制。

## 建议验收目标

下列门槛是教学设计，需由教师用锁定环境预跑校准后冻结，不是已实现指标。

- 4个缺陷全部通过对应隐藏验收；原有12条业务测试不回退。
- 3次指定中断可恢复，模型误报完成被独立验证拦截。
- 10条越界文件/网络请求测试全部被实际执行策略阻止。
- 性能：固定硬件、并发1和5，记录端到端P50/P95、错误率及每成功任务成本；开课前填写项目P95与单任务成本预算，未填写不得宣称通过性能验收。
- 可靠性：每个故障均有可判断的终态；数据撤回、任务重试和越权测试不能由平均成功率掩盖。

## 交付清单

补丁、Harness状态模型、任务轨迹、工具版本、隔离策略与合并回归报告。

同时附README复现入口、数据与模型使用许可、依赖版本、配置示例（无密钥）、测试分母、失败案例、未测项与运行成本。代码交付在学员作业仓库维护。

## 进阶挑战

Codex与Claude Code同题多次重复评估；比较顺序和并行总成本。

先满足基础闭环，再增加挑战；不得用增加模型、框架或Agent数量替代核心质量。
