# 第02课参考答案与评分

本文件供讲师备课与学员首次提交后复盘。下列数值来自**一次真实运行**，证据见[实测报告](reference/mini-autograd-v1/baseline-report.md)及同目录`results.json`、`gradient-check.json`、`bug-diagnostics.json`、`metrics.csv`、`training-history.csv`，非达标分数要求。学员数值可因硬件浮点尾数略有差异，但不应改变结论；独立讲师复现、学员试讲、原生PowerPoint与跨系统验证均未进行。

## 实验A—F关键答案

**A 数据与编码审计**：1280行＝训练720／验证280／测试280；测试240条已知（12类×20条）＋40条未知；客户与表达族各256组且不跨集合。词表345项只从`train.text`构建，`<pad>`=0、`<unk>`=1。长度：训练min 7／p50 16／p95 22／max 27，验证max 26，测试min 8／p50 19／p95 27／max 33；`max_length=128`时三个split截断均为0条。OOV发生率4.9785%＝1065/21392个token。数据版本1.0.0，sha256 `6643d196c8122d9077c7fcf45d1f8ec2c90cd008654eeda0b8f157a1eaaf3bc7`。

**B 形状流转**：`encode_corpus`给出的整集形状为训练(720, 27)、验证(280, 26)、测试(280, 33)——宽度是该split内最长样本，`max_length`只封顶不强制补齐。Notebook第4步取前8条：`(8, 27)` → embedding `(8, 27, 64)` → masked mean `(8, 64)` → linear `(8, 12)`。参数量22860＝embedding 345×64＝22080＋分类头64×12+12＝780。`mask`行和即有效长度，与`sequence_lengths(mask)`、`encode_corpus`第三项一致。

**C 补齐不变性**：只扩宽不截断时，正确实现（`padding_in_mean=False`）在宽度33/40/64/128下池化最大漂移0.0、预测改变0条；缺陷实现漂移0.3401、48条样本中21条预测改变。同一模型同一批测试样本（宽度33）两种实现的池化最大差异0.5243、平均差异0.0734、30/280条预测改变。

**D 梯度校验**：epsilon=1e-6、6行小batch、损失2.4871；最大相对误差embedding 5.149e-05（22080个元素）、分类权重5.259e-05（768个）、偏置1.259e-09（12个）。允许区间表述：embedding与权重在1e-5量级、偏置在1e-9量级；解析与数值梯度的绝对和都约为3.7587／1.5644／1.0018，末位差异即中心差分本身的误差。相对误差接近1通常说明解析梯度为0或反向顺序错误，不是「浮点误差大」。

**E 训练与曲线**：40 epoch后训练loss 1.7221→0.0001，验证loss 1.1882→0.6204，验证macro-F1 0.7756→0.8212。冻结测试四方案：均值池化＋拒识macro-F1 0.4926／覆盖率52.92%（127/240）／未知误收4/40／教学成本0.7857；均值池化强制分类0.7456；第01课TF-IDF＋拒识（冻结）0.3661／40.42%／0/40／0.8107；TF-IDF强制分类0.6100。拒识阈值0.95由验证集按教学成本选出（该点验证成本0.5036）；配对bootstrap 95%区间：均值池化[0.3649, 0.5748]、TF-IDF[0.2531, 0.4531]、差值[−0.0140, 0.2546]跨0，因此不能宣称均值池化稳定优于TF-IDF。

**F 缺陷复现**：补齐参与均值使强制分类macro-F1升到0.7879（准确率79.2%），高于正确实现0.7456，但同一句话的表示会随batch内最长样本漂移，必须判为错误实现。标签错位1位：末轮训练loss 1.6388、验证loss 3.6848、强制分类macro-F1 0.0915（准确率10.4%），接近随机。

**逐类与挑战集快速结论**：强制分类召回为cancel_order／refund_status／payment／change_address／technical_help 100%、exchange 75%、complaint 65%、warranty与product_info 60%、shipping 45%、return与invoice 50%。`challenge-results.csv`分数的解读必须按0.95阈值复核：H11—H14（0.55—0.85）会被拒识；H15（0.977）、H16（0.99998）、H18（1.000）、H20（0.985）会被自信误收；H17仅0.792，会被拒识，不要笼统说H15—H18全部误收——阈值拒识不是安全边界，业务词诱导的域外请求必须单独评测。

## 形状推导与手算标准答案

前向链：`ids (B,S)` → `embedding (B,S,H)` → `masked_mean (B,H)` → `linear (B,C)` → 标量损失（`H=64`、`C=12`）。记`counts = mask.sum(axis=1)`（形状`(B,)`），则`pooled = Σ_s embedded[:,s,:]·mask[:,s,None] / counts[:,None]`；补齐位置的mask为0，既不进分子也不进分母。

反向链（softmax交叉熵，batch内平均）：`dz = (p − y)/B`，形状`(B,C)`；`dW = hᵀ dz`，形状`(H,C)`；`db = Σ_b dz[b]`，形状`(C,)`；`dh = dz Wᵀ`，形状`(B,H)`；`d embedded[b,s,:] = dh[b,:]·mask[b,s]/counts[b]`；`dE`由`np.add.at`按ID散射累加，同一token出现多次则梯度相加而不是覆盖。

手算例子（两样本batch：样本1长度3、样本2长度2，补到`S=3`，`B=2`）：设样本1的词向量为`e_a,e_b,e_c`，样本2为`e_d,e_e`，则`h1=(e_a+e_b+e_c)/3`、`h2=(e_d+e_e)/2`（第3列是补齐，不进分子分母）；`z1=h1W+b`、`z2=h2W+b`；`p=softmax(z)`逐行；`loss=−(ln p1[y1]+ln p2[y2])/2`。于是`dz1=(p1−y1)/2`、`dz2=(p2−y2)/2`；`dW=h1ᵀdz1+h2ᵀdz2`，即`h1[:,None]*dz1[None,:] + h2[:,None]*dz2[None,:]`；`db=dz1+dz2`；`dh1=dz1Wᵀ`、`dh2=dz2Wᵀ`；词向量梯度`de_a=de_b=de_c=dh1/3`、`de_d=de_e=dh2/2`，补齐位为0。核对点：`db`只对batch求和、不经过序列求和，元素又只有12个，所以它的数值误差最小。

## 思考题参考答案

- **A**：OOV降为0有三种可能——词表真的更全、把验证/测试文本也拿去`fit`（泄漏）、或测试集被替换，必须先查`fit`的输入。`max_length`从128改到24时，长度原始分布与词表不变，先变的是截断条数（训练最长27>24，将出现截断），随后才影响有效表示。
- **B**：正确实现按有效长度归一且补齐权重为0，所以同一句话的`(batch, hidden)`与batch组成无关；只有缺陷实现才依赖batch内最长样本。参数量中embedding 22080随词表345×64增长，分类头780＝64×12+12只随隐藏维与类别数增长。
- **C**：漂移0由`masked_mean`里「乘mask（补齐权重0）」与「除以`counts`（有效长度）」共同保证。batch=1时不存在补齐位置，缺陷漂移为0；它只在离线批量评测（宽度由batch内最长决定）时暴露，导致离线指标与线上单条推理不一致。
- **D**：偏置误差最小，因为`db`只在12个类别上对batch求和，不经历embedding的22080维散射累加，截断误差没有机会放大。`epsilon=1e-3`会放大截断误差、`epsilon=1e-9`会放大浮点舍入误差，两者都会让相对误差变大；1e-6附近是本次折中，不能据此推断更大规模算子的正确性。
- **E**：差距同时来自「测试更难」（表达族完全不重叠、测试更长、含否定与状态条件）与「采样」（240条已知在不同表达族上抽样）。阈值0.95使已知覆盖率降到52.92%，被拒识的已知样本仍按错误计入macro-F1，所以0.4926远低于强制分类的0.7456。裁剪是否被触发：参考运行的`results.json`没有记录命中次数，不要凭猜断言；可对同一seed复跑并打印每步梯度范数或`np.clip`前后差异来统计。
- **F**：补齐参与均值的测试F1更高不是正确性证据——它的池化向量随batch内最长样本漂移，离线评测与线上单条推理会给出不同预测；修复应回到「补齐权重0、按有效长度归一」，而不是改测试集。标签错位1位时输入与标签不再对应，但错位映射固定，模型仍在记忆错误配对；均值池化会让部分文本表示相互接近，因此训练loss停在1.6388而验证loss升到3.6848（比随机更差）（此处为教学解释，参考运行未单独测量表示碰撞率）。

## 课堂提问与延伸答案

「为什么不用PyTorch？」本课目的是让维度和梯度可见，手写一遍再学框架更省力；这不表示生产应手写反向，后续课程会对照框架实现。
「均值池化丢了什么？」词序、否定范围、状态条件与多诉求结构；像`H01`（否定退货、主诉求查款）这类依赖词序的句子最脆弱，均值池化把权重平摊到所有token上。
「意图分类正确就等于客服问题解决了吗？」不等于；分类只是分流正确性的代理指标，知识命中、权限校验、业务执行与用户确认都不在其中。
「提交数值与参考略有差异怎么办？」先核对数据hash、配置与seed；本课训练在固定seed下应逐位一致，不一致说明环境或代码有差异；硬件差异主要影响时延（本次Python 3.12.13、单线程训练3.27秒），不改变质量结论。
