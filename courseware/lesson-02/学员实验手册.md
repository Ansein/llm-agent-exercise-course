# 第02课学员实验手册

[教学包入口](README.md) · [原课程大纲](../../lessons/02-张量计算与文本表示基础.md) · [第01课手册](../lesson-01/学员实验手册.md)

## 任务背景与交付范围

你是虚构设备企业的技术工程师，需要在不使用PyTorch等框架的前提下讲清客服意图分类模型的数据流：字符如何变成ID、ID如何补齐成张量、张量如何经均值池化与线性头得到12类分数，以及手写反向是否真的正确。本课沿用第01课冻结的合成客服问句与同一测试集，只比较数据表示与池化方式，不实现问答生成、订单操作或实际退款。

成功标准是可复现、形状正确、能证明梯度正确、能定位注入缺陷。测试macro-F1不高可以得到高作业成绩；伪造结果、改测试集标签或把缺陷实现当正确交付不能通过。

## 本手册的使用方式

课堂75分钟按A→F顺序推进：A、B、C是数据与形状基础，D是反向正确性证据，E是训练与曲线解读，F是故障定位。每节给出「目的／输入／执行入口／检查点／常见错误」，建议先跑通讲解版Notebook，再在自己的副本上改算子。课后2—3小时完成练习、失败案例与报告。

## 环境准备与数据前提

使用Python 3.12；依赖与第01课相同，安装后全部实验离线完成，无GPU、无API调用。安装与运行命令见[教学包README](README.md)。若没有Jupyter前端，用`execute_notebook.py`导出HTML即可查看全部代码与输出；课堂不必安装JupyterLab。

本课不重新生成数据：`src/data.py`读取`courseware/lesson-01/data/`下的`samples.csv`、`manifest.json`、`templates.json`、`challenges.csv`并校验manifest中的sha256，同时读取第01课`reference/baseline-v1/predictions.csv`做配对对照。数据是合成教学材料，不上传真实客户信息。把输出写进新建的`runs/`子目录，不覆盖`reference/`。

数据前提核对：1280行＝训练720／验证280／测试280；测试集240条已知（12类×20条）＋40条未知；客户与表达族不跨集合。hash不匹配时不要就地改数据，应回到第01课教学包恢复原始文件，或新建数据集版本（版本1.0.0，sha256见`manifest.json`）。

## 实验A：数据与编码审计（10分钟）

目的/输入/入口：确认数据冻结、分词口径与长度/OOV分布，建立后续全部实验的输入前提。输入是第01课冻结数据与`config.json`中的`max_length`、`ngram_max`；在Notebook的`load_frozen()`与交叉表单元运行审计，或运行完整CLI（`.venv/bin/python courseware/lesson-02/src/evaluate.py --output courseware/lesson-02/runs/audit-a`）后读`data-audit.json`、`encoding-audit.json`。
检查点：词表345项且只从`train.text`构建；`<pad>`=0、`<unk>`=1；训练集长度min 7／p50 16／p95 22／max 27，测试集max 33；`max_length=128`时截断0条；OOV发生率4.9785%（1065/21392个token）。注意`evaluate.py`目前只有`--output/--data-dir/--verbose`三个参数，模块文档字符串提到的`check`、`gradient-check`子命令尚未实现，审计输出请用Notebook或完整CLI获取。
常见错误：用全量文本fit词表会让测试字符提前进入词表；把含类别名的`template_id`当特征属于泄漏；把OOV只统计到验证集而漏掉测试集。

思考题：如果测试集OOV率降到0，是模型变好了，还是评测口径变了？把`max_length`从128改到24，最先受影响的是词表、长度分布还是截断比例？

## 实验B：文本→ID→张量的形状流转（15分钟）

目的/输入/入口：把一条中文问句逐步映射成四层张量并能手写每层形状。输入是`tokenizer.encode`、`pad_batch`、`encode_corpus`与一个未训练的`MeanPoolClassifier`；在Notebook「2. 文本→ID→张量」与「4. 全流程形状与参数量」两节调用`shapes.forward(train_arrays[0][:8], train_arrays[1][:8])`，涉及`embedding`、`masked_mean`、`linear`三个算子。
检查点：`(batch, seq)` → `(batch, seq, hidden)` → `(batch, hidden)` → `(batch, classes)`；「4. 全流程形状」单元取训练集前8条时实际为(8, 27)→(8, 27, 64)→(8, 64)→(8, 12)（宽度等于该batch内最长样本；训练集全局宽度27、验证集26、测试集33，`max_length=128`只是上限）；参数量22860＝embedding 22080＋分类头780；mask行和等于该样本有效长度（`sequence_lengths(mask)`），补齐位置为0。
常见错误：对`seq`维直接sum而忘记除以有效长度；`hidden_dim`与embedding表第二维不一致；把`indices`写成一维再传给`embedding`（该函数会明确报错）。

思考题：同一句话单独推理与放进一个长句batch，`(batch, hidden)`为何应当相同？参数量22860中哪部分随词表增长、哪部分只随类别数增长？

## 实验C：补齐与mask不变性（10分钟）

目的/输入/入口：证明正确的masked mean与batch内最长样本无关，而缺陷实现会漂移。输入是同一批已编码样本与同一模型，只改变补齐宽度和是否把补齐计入均值；用`pad_batch(..., max_length=...)`配`masked_mean`，完整对照用`batch_width_invariance(model, ids, mask, labels)`（宽度33/40/64/128）。
检查点：只扩宽、不截断时，正确实现（`padding_in_mean=False`）池化最大漂移0.0、预测改变0条；把补齐计入均值（`padding_in_mean=True`）漂移0.3401、48条样本中21条预测改变；用`padding_sensitivity`看同一模型同一批样本的池化最大差异0.5243。
常见错误：以为「模型自己会学会忽略padding」；训练时传mask而推理时忘传；把固定补到128当必要条件（按batch内最长补齐即可，`max_length`只是上限）。

思考题：漂移为0是哪一步数学保证的？请指出具体除法与权重。若线上每次只推理一条样本（batch=1），缺陷实现的漂移会变大还是变小，为什么？

## 实验D：手写反向与数值梯度校验（15分钟）

目的/输入/入口：用中心差分证明`autograd.py`的手写反向方向正确，并能解释各参数误差差异。输入是独立初始化的小模型、训练集前6行小batch与`epsilon=1e-6`；调用`gradient_check(check_model, train_arrays[0], train_arrays[1], train_labels, n_rows=config['gradient_check_rows'])`，底层为`backward(loss)`与`numerical_gradients(loss_value, model.parameters, epsilon)`，误差由`relative_error`计算。
检查点：最大相对误差embedding 5.149e-05（22080个元素）、分类权重5.259e-05（768个）、偏置1.259e-09（12个），与`gradient-check.json`一致；小batch损失2.4871；1e-5量级来自中心差分在float64下的截断与舍入误差，不能据此判定反向写错。
常见错误：忘记先`zero_grad()`导致梯度累加；把非标量损失传给`backward`；只校验一次就宣称所有算子正确（本课只覆盖查表、池化、线性与交叉熵）。

思考题：为什么偏置的相对误差比embedding小四个数量级？把`epsilon`改成1e-3或1e-9，误差会怎样变化，这说明了什么？

## 实验E：训练最小分类器并读曲线（15分钟）

目的/输入/入口：跑完一次前向→反向→更新，观察训练/验证分离并给出业务解释。输入是720条训练样本，Adam、学习率0.05、batch 64、40 epoch、梯度裁剪5.0、seed 20260915；调用`train_model(model, train_arrays, train_labels, known_validation_arrays, known_validation_labels, verbose=True)`，或运行完整CLI后读`training-history.csv`与`training-curves.png`。
检查点：训练loss 1.7221→0.0001，验证loss 1.1882→0.6204，验证macro-F1 0.7756→0.8212；能说明验证loss不再下降不等于代码错误，而是本数据训练与测试表达族完全不重叠的预期差距；冻结测试上带拒识macro-F1 0.4926、覆盖率52.92%，强制分类0.7456，拒识阈值0.95只由验证集成本选出。
常见错误：为压低验证loss一直加epoch（记忆训练表达）；用测试集选epoch或阈值；把验证集40条未知样本计入闭集验证损失（本实现已用`known_validation`排除）。

思考题：验证macro-F1 0.8212与冻结测试macro-F1 0.4926差距很大，哪部分来自测试更难、哪部分来自表达族采样？如何在不改结果的前提下检查梯度裁剪5.0是否被触发？

## 实验F：缺陷复现与定位（10分钟）

目的/输入/入口：亲手制造两个典型缺陷，建立「指标变好也可能是错的」判断。输入是同一训练好的模型与同一测试集，唯一变化是待验证的实现选择；入口为`padding_sensitivity(model, test_arrays[0], test_arrays[1], test_labels, config['max_length'])`、`batch_width_invariance(...)`、`run_experiment(..., padding_in_mean=True)`、`run_experiment(..., label_shift=1)`。
检查点1（补齐参与均值）：强制分类macro-F1反而升到0.7879；同一模型同一批样本池化最大差异0.5243、30/280条预测改变；扩宽画布时漂移0.3401，正确实现为0.0。
检查点2（标签错位1位）：末轮训练loss仍为1.6388、macro-F1降至0.0915、准确率10.4%，接近12类随机水平（1/12≈8.3%）；真实项目里常表现为「训练正常但预测几乎全是同一类」。
常见错误：只看F1上升就判定实现更优；把标签错位当成学习率或初始化问题；改动测试标签来「修复」指标。

思考题：为什么「补齐参与均值」的测试F1更高却必须判为错误实现？请给出上线后的具体出错场景。标签错位1位时训练loss停在1.6388而不是继续下降，说明误差信号发生了什么？

## 常见故障排查

| 现象 | 排查 |
|---|---|
| `ModuleNotFoundError` | 确认运行的是安装了依赖的`.venv`解释器；`sys.path`需含`courseware/lesson-02/src` |
| 找不到第01课数据 | 本课只读引用`courseware/lesson-01/data/`；确认第01课教学包完整，不要另复制一份 |
| 数据hash不匹配 | 检查是否用Excel重存CSV（编码/换行改变也会触发）；不要在`runs/`里改冻结数据 |
| 输出目录非空被拒绝 | `prepare_output`拒绝覆盖；换新的`runs/<新目录>`，不覆盖`reference/` |
| Notebook内核端口受限 | `execute_notebook.py`需本机回环端口；受管环境用获准的本地Jupyter，或只用CLI（CLI不依赖端口） |
| 图表中文标签缺失 | `evaluate.py`按平台探测CJK字体，找不到时回退为ASCII标签（如`padding_in_mean`），不影响数值 |
| 改了代码却像没生效 | 清理`src/__pycache__`或换新输出目录；Python会复用旧字节码，先确认加载的是当前源文件 |

没有亲自跑通的命令或未运行的实验不能写成已完成。参考实现见`reference/mini-autograd-v1/`，评分见[参考答案与评分](参考答案与评分.md)。
