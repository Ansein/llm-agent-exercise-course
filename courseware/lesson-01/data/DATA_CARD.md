# 客服意图教学数据卡

## 来源与使用范围

数据集：`lesson01-intent-synthetic`，版本1.0.0，生成种子20260914。所有文本由本课程为虚构“星舟设备服务”设计，未采集真实客户或企业信息；customer_id不对应任何真实个人。第三方原始数据使用：无。生成器与核心表达随教学包交付，允许在本项目培训、复现和课程衍生练习中使用；对外分发时保留合成标识及本数据卡，不暗示真实客户授权或真实业务代表性。仓库其他材料的使用权不由本数据卡另行授予。

240个已知核心表达×5种固定礼貌包装=1200条、12个业务意图。16个域外核心表达×5=80条未知样本，另计入文件。不要把1280条全称为1200条，也不要把包装扩写当作1200个独立人工案例。

另有24条人工设计挑战案例，覆盖否定、缩写、多意图、指代不明和带业务关键词的域外请求。它们在模型评测前写入，不进入训练、阈值选择或主测试指标。

## 标注规范

| 标签 | 中文 | 边界 |
|---|---|---|
| shipping_status | 物流查询 | 查发货、运输、配送状态；改目的地属于change_address |
| cancel_order | 取消订单 | 未收货且明确撤销订单；已签收退回属于return_request |
| refund_status | 退款进度 | 已发起退款后查询款项；新申请退回商品属于return_request |
| return_request | 退货申请 | 已收货后退回，不保留商品 |
| exchange_request | 换货申请 | 保留购买意愿，更换型号/规格或换新 |
| invoice | 发票问题 | 开票、税号、抬头、票据获取或更正 |
| payment | 支付问题 | 收银、扣款、交易失败、支付状态 |
| change_address | 修改收件信息 | 地址、收件电话或姓名更改 |
| warranty | 保修维修 | 损坏、质保、送修、维修进度 |
| technical_help | 安装使用 | 已有设备的配置、使用与排障指导 |
| complaint | 服务投诉 | 对人员/服务的正式投诉升级 |
| product_info | 售前咨询 | 购买前的型号、库存、规格与兼容性 |
| unknown | 未知或需澄清 | 主数据是域外；挑战集还包括多诉求及无上下文，执行含义都是停止单标签自动路由 |

主诉求优先于被否定或作为背景提及的意图。两个独立有效诉求不强行选一个；本节单标签系统用unknown表示需拆解/澄清，后续Agent课程再实现多任务。不得只按出现关键词标注。真实场景中的“退钱”不总是退款查询，需要结合是否已申请；本样板用上述明确边界，歧义样例放挑战集。

## 切分与泄漏控制

每类前12个核心表达分给训练（60条/类），接着4个验证（20条/类），最后4个测试（20条/类）；客户ID和表达族同步独占集合。已知意图合计720/240/240。未知只在验证40、测试40。因此CSV总计train=720、validation=280、test=280。

这不是随机IID切分：测试特意放入否定、同义和背景干扰，表达难度高于训练。低分支持“当前基线在这些困难表达上失败”，不能支持“所有传统NLP都很差”。验证也只含4族/类，阈值可能不稳。真实项目应根据部署目标选择时间/客户/文档族划分，单独设压力测试。

归一化检查去除Unicode宽窄差异、空白和标点后的完全重复；另用训练拟合的字符TF-IDF做测试到训练相似性诊断。诊断不参与模型选择。无跨组与无高相似度标记不等于无语义关联。礼貌包装跨集合共享；客户组与模板组一一对应是人为简化，实际应分别审计。
