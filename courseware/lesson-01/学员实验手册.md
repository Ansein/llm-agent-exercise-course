# 第01课学员实验手册

[教学包入口](README.md) · [原课程大纲](../../lessons/01-业务问题建模与传统NLP基线.md)

## 任务背景与交付范围

你是虚构设备企业的技术工程师，需要比较两种客服意图路由方案。输入一条问句，输出12个标签之一或unknown（交人工/澄清）。本节不实现问答生成、订单操作或实际退款。

成功标准是可复现、口径正确、能解释失败。F1低可以得到高作业成绩；伪造结果或偷看测试标签调参不能通过。

## 环境准备

使用Python 3.12；依赖已安装后，全部实验不需要网络、API或GPU。安装与执行命令见README。建议课前完成安装，课堂只执行。若没有Jupyter前端，直接运行CLI与`execute_notebook.py`，打开导出的HTML即可查看全部代码和输出。

运行前读取[data/DATA_CARD.md](data/DATA_CARD.md)。所有数据是合成教学材料，不上传真实客户信息。保留原始数据与reference目录，将你的输出放在新建runs子目录。

## 实验A：业务指标与数据审计（15分钟）

1. 写出意图分类、知识检索与自动解决的三个不同成功定义。注明每个分母。
2. 打开samples.csv，解释1280行为什么不与“1200条已知意图”矛盾。
3. 运行Notebook第1步，提交各split、各类别计数以及客户/模板交叉数。
4. 找出不允许作为输入特征的列。解释template_id为什么尤其危险。
5. 说明“每类20条测试”与“每类4个表达族”的区别。

检查点：训练720、验证280、测试280；test中已知240、unknown40；同一客户与表达族只能出现在一个集合。若hash不匹配，恢复原始数据或重新生成到新目录比较，不删除校验代码。

## 实验B：两种分类基线（15分钟）

1. 用`KeywordRules.explain`查看“开具发票”和“不要取消订单，只是改收货地址”的命中结果。
2. 查看Pipeline，指出训练词表、IDF、分类权重的唯一fit入口，确认只用train.text和train.intent。
3. 手算讲义中的D1=[退款,到账]的IDF与L2归一向量。
4. 用三个你自己编写的**开发样例**调用两个方案，记录差异及可能原因，不修改冻结数据。

检查点：能说明规则的多命中拒识与模型分数不是同一个概念。不要把模型分数叫作已经校准的正确率。

## 实验C：验证阈值与成本（15分钟，含5分钟休息）

1. 读取config中的教学成本：known_wrong=3、known_reject=1、unknown_accept=5。
2. 运行验证集网格搜索，找到最小cost及平局规则。
3. 比较阈值0.10、0.25、0.50的已知覆盖与未知误收。
4. 写一句解释：为什么拒绝所有请求不能被称为优秀客服？

检查点：所选阈值来自validation，不来自test。规则基线采用唯一匹配，没有使用TF-IDF阈值。

## 实验D：最终测试与图表（15分钟）

运行完整CLI或Notebook第5步，保存输出。读取metrics.csv、逐类文件和两张混淆矩阵，回答：

- 已知macro-F1是否把unknown样本当作第13类平均？本实现没有；但已知被拒识仍记错误。
- 模型强制分类为什么所有未知请求都被误收？它只有12个已知类别。
- 哪些类别最常被拒识？用逐类召回或矩阵证据说明。
- F1和成本是否给出同一方案选择？
- 该测量是本地分类调用，能否代替客服处理时长？

检查点：报告质量与覆盖率时带上分母；不把0/40域外误收称为系统绝不误收。

## 实验E：失败与困难样本（15分钟＋课后补全）

课堂分析5例，课后补足至少20例。优先从predictions.csv中的不同template_id选择失败，避免5个礼貌包装占满作业。可另外使用24条challenge-results补充否定、多诉求和域外诱导。

每例写：样本ID、原文、金标准、规则预测、模型预测、错误/正确原因、业务风险、拟验证的改进。若样本预测正确，明确是困难但正确，不能伪称失败。最终至少20例应来自独立表达，注明主测试或挑战来源。

建议重点：H03否定了维修却预测维修；H16翻译请求错误触发取消订单；H19/H20对比未寄出与已签收；H21/H22区分售前与安装。

检查点：改进建议是“如何验证假设”，而不是“给这条测试加专属关键词”。

## 交付与验收（25分钟）

按[作业报告模板](作业报告模板.md)提交到自己的作业目录，附配置、版本、数据hash、逐样本预测、指标与至少20例分析。现场展示一个正常例子和一个失败例子，并复跑一条命令。

必交文件可包括自己的report.md、config.json、predictions.csv、metrics.csv、error-analysis.csv以及复现命令；不要把虚拟环境或真实企业数据打包。可以引用包内参考文档，但你自己的结果必须可识别。

## 课后扩展：只能在开发数据上探索

任选一项：比较字符1—2与2—4 gram；调整错误成本；增加独立开发样例研究否定或域外。先声明变量与预期，再用验证集选方案。若已经观察过原测试，可将其当回归集并明确“已见”；新的泛化结论须另建未见测试。

业务迁移题：选择一个脱敏部门流程，定义错误成本矩阵与转人工条件，说明为什么也许不需要LLM。不要提交客户姓名、电话、工单原文或密钥。

## 常见故障

| 现象 | 排查 |
|---|---|
| ModuleNotFoundError | 检查正在运行的Python是否来自安装依赖的虚拟环境 |
| 找不到src或data | CLI支持任意工作目录；Notebook需从仓库或包内启动 |
| 输出目录非空 | 换一个新的runs目录，不覆盖reference |
| 数据hash失败 | 检查是否用Excel重存了CSV，编码/换行改变也会触发 |
| 内核端口权限被拒 | Notebook需要本机loopback端口；CLI不需要。受管环境使用获准的本地Jupyter环境 |
| 图表没有中文标签 | 矩阵按01—12数字编码，Notebook和报告有完整中文图例，避免缺少CJK字体 |
| 与参考耗时不同 | 时延受CPU与系统负载影响；先比较数据hash、阈值和质量指标 |

没有亲自参加的试讲或未运行的代码不能写成已完成。评分见教师发布的量表。
